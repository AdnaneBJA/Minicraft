# Load-testing bots: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Go tool, `loadtest/`, that runs N bot players against a minicraft-server and reports input latency, tick
jitter, join time, throughput, failures and server CPU and memory.

**Architecture:**
- **Protocol:** a protocol-level Go client mirroring `net-common/protocol.*`, kept honest by byte fixtures generated
  in C++.
- **Bots:** each bot is a reader goroutine plus an actor goroutine over one WebSocket, recording into shared,
  concurrency-safe histograms.
- **CLI:** drives the steady, ramp and soak modes, prints a live line and writes JSON and Markdown reports.

**Tech Stack:** Go 1.25+, `github.com/coder/websocket`, `github.com/shirou/gopsutil/v4`; C++20 and GoogleTest for
the fixtures; GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-09-loadtest-design.md`

## Global Constraints
- **Production is never a target.** The tool refuses non-local and non-private hosts unless
  `--i-know-this-is-not-local` is given.
- **The wire format matches C++ exactly:** little-endian, the same type numbers (0–9), and the same limits (names ≤ 12,
  chat ≤ 80, error ≤ 200, turns ≤ 64, commands per turn ≤ 18, history ≤ 6 h of ticks).
- **Decoders never panic** on any input.
- **Bot names** are `bot%03d`, and `probe%03d` for soak-mode probes.
- **Module:** `github.com/AdnaneBJA/Minicraft/loadtest` (separate from `stats/`).
- **Commits:** no Claude/AI lines. Branch `loadtest`.

## Review Focus
1. **The server refuses the 33rd connection at the socket level** (`maxConnections` 32): the bot must count it as a
   connection failure, not hang. Test: `TestBotCountsRefusedConnection` (fake server that closes the socket at once).
2. **A huge Joined history** (a soak run on an old world) must decode within its limits and not blow memory: decoding
   streams the ticks without keeping them. Test: `TestDecodeJoinedLargeHistory` (100k ticks).
3. **Ctrl+C during the ramp** still writes the report with the partial data. Test: `TestRunCancelledWritesReport`.
4. **Clock jumps / no ticks at all:** zero ticks means jitter reports n=0, not NaN or a panic. Test:
   `TestReportEmptyHistograms`.
5. **A bot's Input write blocking** (a slow server) must not stall its reader: they're separate goroutines with a
   write timeout. Test: `TestSlowWriterDoesNotBlockReader`.

### Task 1: The protocol in Go, with fixtures generated by C++

**Files:**
- Create:
  - `server/tests/protocol_fixtures.cpp` (a gtest that writes the fixtures when `WRITE_PROTOCOL_FIXTURES=1`, and
    otherwise compares them)
  - `loadtest/protocol/testdata/*.bin`
  - `loadtest/go.mod`, `loadtest/protocol/protocol.go`, `loadtest/protocol/protocol_test.go`
- Modify: `CMakeLists.txt` (add the test file to `server_tests`)

**Interfaces (produced):**
```go
package protocol
const (Hello, Input, Command, Chat, StateHash, Welcome, Joined, Tick, ChatLine, Error MsgType = 0..9)
type Keys uint8 // bit0 left, bit1 right, bit2 up, bit3 down, bit4 attack, bit5 pressed
type Command struct{ Kind uint8; A, B, C, D int32; Text string }
type Turn struct{ PlayerID int32; Keys Keys; Commands []Command }
type TickMsg struct{ Tick int32; Turns []Turn }
func EncodeHello(name string) []byte
func EncodeInput(k Keys) []byte
func EncodeChat(text string) []byte
func EncodeWelcome(id int32) []byte                    // for the fake server
func EncodeJoined(seed uint32, history []TickMsg) []byte
func EncodeTick(t TickMsg) []byte
func EncodeChatLine(from, text string) []byte
func EncodeError(text string) []byte
type Message struct{ Type MsgType; PlayerID int32; Seed uint32; HistoryLen int; Tick TickMsg; From, Text string }
func Decode(b []byte) (Message, error) // Joined: counts and skips the history ticks (HistoryLen), doesn't keep them
func DecodeJoinedHistory(b []byte) (uint32, []TickMsg, error) // fixtures and tests only
```

The fixture examples (the same values in C++ and Go):
- `hello.bin`: Hello{"Alice"}
- `input.bin`: Input{moveX = 1, moveY = −1, attack, pressed}
- `chat.bin`: Chat{"hi there"}
- `welcome.bin`: Welcome{7}
- `joined.bin`: Joined{seed 99, history [Tick 1: player 7 keys 0 with commands [Join "Alice"]; Tick 2: player 7 keys
  {right}, no commands]}
- `tick.bin`: Tick{42: [player 3, keys {left, attack}, Craft(a = −1, b = 2)], [player 7, keys {}, none]}
- `chatline.bin`: ChatLine{"Alice", "hello"}
- `error.bin`: Error{"Name already in use"}

Steps:
- [ ] **Step 1: C++ fixture test.**
  - `ProtocolFixtures.MatchCommittedFiles` encodes each example with `protocol::encode`.
  - With `WRITE_PROTOCOL_FIXTURES=1` it writes them to `${MINICRAFT_SOURCE_DIR}/loadtest/protocol/testdata/<name>.bin`
    (the path comes from a compile definition `MINICRAFT_SOURCE_DIR="${CMAKE_SOURCE_DIR}"` on `server_tests`).
  - Otherwise it reads each file and `EXPECT_EQ`s the bytes.
- [ ] **Step 2:** Build and run without the files. Expected: FAIL (no file). Run once with
  `WRITE_PROTOCOL_FIXTURES=1` to create them, then plain again. Expected: PASS. Commit the files.
- [ ] **Step 3: Go tests (RED):**
  - `TestFixturesDecode`: each file decodes to the expected values; `joined.bin` through `DecodeJoinedHistory`.
  - `TestFixturesReencode`: the encoders reproduce each file byte for byte.
  - `TestDecodeRejectsMalformed`, a table of cases, all errors and no panics: empty; unknown type 10; truncated i32;
    a string length of −1; a name of 13 bytes; a turn count of 65; a command count of 19; trailing byte; a command kind
    of 9; history count < 0.
  - `TestDecodeJoinedLargeHistory`: 100,000 ticks of 2 turns encode and decode with `HistoryLen` 100,000. Allocation
    stays below 10 MB, checked with `testing.AllocsPerRun`-style `runtime.MemStats` deltas.
  - `FuzzDecode`: no panics (seeded with the fixtures).
- [ ] **Step 4: Implement** `protocol.go`:
  - a reader with `ok` and failure semantics, as in C++ `ByteReader`;
  - the writer;
  - `Decode` checks `atEnd` after reading.
- [ ] **Step 5:** `go vet ./... && go test -race ./...` passes; the C++ fixture test passes.
- [ ] **Step 6: Commit.** `feat(loadtest): the game protocol in Go, checked against fixtures from the C++ side`

### Task 2: Metrics and server process sampling

**Files:** `loadtest/metrics/{histogram,counters}.go` plus tests; `loadtest/procstat/procstat.go` plus test

**Interfaces (produced):**
```go
type Histogram struct{ /* mutex, log buckets 1µs..60s at ~1% */ }
func NewHistogram() *Histogram
func (h *Histogram) Record(d time.Duration)
func (h *Histogram) Summary() Summary // n, p50, p95, p99, max, mean
type Summary struct{ N int64; P50, P95, P99, Max, Mean time.Duration }
type Counters struct{ Connected, Joined, JoinFailed, Refused, Dropped, Messages, Bytes, ChatLines, Superseded atomic.Int64 }
type Sampler struct{ /* ... */ }
func StartSampler(ctx context.Context, pid int32, every time.Duration) (*Sampler, error)
func (s *Sampler) Stats() ProcStats // MaxCPU, AvgCPU float64; MaxRSS, AvgRSS uint64; Samples int
```

Steps:
- [ ] **Step 1: Tests (RED):**
  - `TestPercentilesUniform`: 1..10000 µs gives p50 ≈ 5000 µs ±2%, p99 ≈ 9900 µs ±2%.
  - `TestPercentilesSkewed`: 99 at 1 ms and 1 at 1 s gives p99 ≈ 1 ms, max = 1 s.
  - `TestReportEmptyHistograms`: an empty histogram's summary is N = 0 with all zeros, and no NaN.
  - `TestConcurrentRecord`: 16 goroutines × 10k records under `-race` gives N = 160k.
  - `TestSamplerOwnProcess`: sampling `os.Getpid()` for 1.2 s gives ≥ 1 sample and RSS > 0.
- [ ] **Step 2: Implement.** Bucket index `int(math.Log(float64(ns)/1000) / math.Log(1.01))`, clamped; percentiles
  walk the buckets; the max is exact.
- [ ] **Step 3: Tests pass; commit.** `feat(loadtest): latency histograms, counters and process sampling`

### Task 3: A bot, tested against a fake server

**Files:** `loadtest/bot/bot.go`, `loadtest/internal/fakeserver/fakeserver.go`, `loadtest/bot/bot_test.go`

**Interfaces (produced):**
```go
type Shared struct{ Latency, Jitter, Join *metrics.Histogram; Counters *metrics.Counters }
type Config struct{ URL, Name string; Seed int64; ChatEvery time.Duration }
func Run(ctx context.Context, cfg Config, s *Shared) error // returns when ctx ends or the connection drops
// fakeserver
type Server struct{ URL string; Delay time.Duration; RejectNames map[string]bool; /* ... */ }
func Start(t testing.TB) *Server   // httptest + coder/websocket; Welcome, Joined, 60 Hz ticks echoing each player's keys after Delay
func (s *Server) CloseAll()        // drops every connection
func (s *Server) RefuseConnections() // closes new sockets right after accepting them
```

Steps:
- [ ] **Step 1: Tests (RED):**
  - `TestBotJoinsAndPlays`: 2 s gives Joined = 1, Latency.N > 0, Jitter.N > 50.
  - `TestInputLatencyMeasured`: with Delay 50 ms, Latency p50 is between 50 and 75 ms.
  - `TestNameInUseIsJoinFailure`: JoinFailed = 1 and `Run` returns an error.
  - `TestBotCountsDrop`: `CloseAll` after 500 ms gives Dropped = 1 and `Run` returns.
  - `TestBotCountsRefusedConnection`: with `RefuseConnections`, Refused = 1.
  - `TestSlowWriterDoesNotBlockReader`: the fake server stops reading the bot's messages (no reads for 2 s) while
    still sending ticks, and Jitter.N keeps growing.
- [ ] **Step 2: Implement.**
  - `bot.Run`: dial with a 5 s timeout; Hello; read until Welcome and Joined (or Error, which is a join failure);
    record the join time.
  - Then start the actor goroutine: walk, attack and chat, each write with a 1 s timeout. It sends to a buffered
    channel of key changes with the time sent; the reader holds only the latest pending one.
  - The reader loop handles Tick (jitter, then latency if its own turn's keys equal the pending keys), ChatLine and
    Error.
  - Count Messages and Bytes.
  - On a read error after joining: Dropped++, unless ctx is done.
- [ ] **Step 3: Tests pass with `-race`; commit.** `feat(loadtest): bots that join, play and measure input latency`

### Task 4: The CLI: modes, the live line, reports, safety

**Files:** `loadtest/cmd/loadtest/main.go`, `loadtest/run/run.go` (modes), `loadtest/report/report.go`, tests for
`run` and `report`, `loadtest/README.md`

**Interfaces (produced):**
```go
type Options struct{ URL string; Bots int; Ramp, Duration time.Duration; Mode string; Step int; Every time.Duration; MaxP99 time.Duration; ProbeEvery time.Duration; ServerPID int32; Seed int64; AllowRemote bool }
func CheckTarget(url string, allowRemote bool) error
func Run(ctx context.Context, o Options, live io.Writer) (report.Result, error)
type Result struct{ /* config, duration, summaries, counters, proc stats, steps []Step, BreakingPoint *Break, JoinProbes []Probe */ }
func WriteFiles(r Result, base string) error // base.json + base.md
func LiveLine(elapsed time.Duration, bots, target int, s Snapshot) string
```

Steps:
- [ ] **Step 1: Tests (RED):**
  - `TestCheckTarget`, a table: localhost, 127.0.0.1, [::1], 10.x, 192.168.x and 172.16.x are allowed; `wss://` with a
    public name or IP is refused unless allowed; garbage URLs are refused.
  - `TestRunSteadyAgainstFake`: 4 bots for 2 s; the result has Joined = 4 and a latency N > 0.
  - `TestRunRampFindsCap`: the fake server refuses connections beyond 6; ramp with step 2 every 300 ms up to 10 bots
    gives a breaking point of `{Bots: 8, Cause: "connections refused"}`.
  - `TestRunCancelledWritesReport`: cancel after 500 ms; `Run` returns a partial result; `WriteFiles` writes both
    files.
  - `TestMarkdownReport`: contains the "Input latency" table and the p99 values.
- [ ] **Step 2: Implement.**
  - Modes as in the spec. Breaking-point check at the end of each ramp step: p99 of that step's latency (a fresh
    histogram per step) over MaxP99, or Refused/Dropped increased during the step.
  - Soak probes: a probe bot (`probe%03d`) joins, records the join time and history length, and leaves.
  - The live ticker every second.
- [ ] **Step 3: `loadtest/README.md`.** Usage, modes, the safety flag, the throwaway EC2 recipe (launch a t3.micro →
  `docker run -p 7777:7777 <image built from server/Dockerfile>` → run with `--i-know-this-is-not-local` → terminate),
  and how to read the report.
- [ ] **Step 4: Tests pass; commit.** `feat(loadtest): steady, ramp and soak modes with live output and reports`
